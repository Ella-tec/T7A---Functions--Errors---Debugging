# T7A – Functions, Errors & Debugging

## **Outcome:**

Learners will leave this session able to:

- Write and call reusable functions,
- Handle basic errors systematically, and
- Document their debugging process.

## **Artifact:**

Refactored code that:

- Uses at least two functions,
- Includes error handling and comments,
- Captures at least one bug fix with a clear commit message.

## **Rubric for Functions & Debugging Artifact**

| **Level** | **What the Artifact Shows**|
| -- | --- |
| **Limited** | Code runs with repeated blocks. Functions missing. Errors unresolved. No debugging notes or commits.                                                                                  |
| **Emerging** | At least one function is present but incomplete. Errors fixed inconsistently. Debug ritual not followed. Commit missing or vague.                                                     |
| **Developing** | Two functions written and called correctly. One error debugged with partial ritual use. Commit message present but generic. Comments are minimal.                                     |
| **Proficient** | Two or more reusable functions implemented. Error debugged systematically with ritual. Clear commit message ( *“fix: root cause…”* ). Comments explain fixes.                                               |
| **Advanced** | Functions well-structured, reusable, and efficient. Debug ritual fully documented. Logging standard applied. Commit messages detailed. Artifact shows professional debugging culture. |
